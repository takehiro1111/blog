## 4. Otelとは？
- テレメトリデータ（トレース・メトリクス・ログ）を収集・エクスポートするためのOSSフレームワーク,ツールキットです
- CNCFプロジェクトで開発されていて、オブザーバビリティツールとしてはデファクトスタンダードになりつつあります
- 様々な言語のSDKが提供されており、アプリケーションの計装を統一的に行えます
- ベンダーに依存していないため、バックエンドのプラットフォームを自由に選択することができます

## 5. Otelを構成するコンポーネント
### 仕様・規約
- `OTLP`: テレメトリデータの標準プロトコル
- `Semantic Conventions`: 命名規則の標準化

### 開発者向け
- `API / SDK`: 各言語でテレメトリを生成するためのライブラリ
- `Instrumentation Libraries`: フレームワーク向けの計装ライブラリ
- `Auto Instrumentation`: コード変更なしで自動計装

### インフラ向け
- `Collector`: テレメトリの受信・加工・転送を担うプロキシ(ECS, EKSだとサイドカー的な役割)
- `K8s Operator / Helm Charts`: Kubernetes環境向けのデプロイツール

### トレースとは？
- 分散システム内での処理の流れを可視化したものです
  - 例えば、ECサイトでユーザーが商品を購入するとしても、1つのリクエストがシステム内の複数のサービス（認証、在庫確認、決済など）をどのように通過していったかを示す足跡的な役割を担います
  - どのサービスがどのサービスを呼び出したか、その処理にどれくらい時間がかかったかレイテンシーが可視化され、どの処理がアプリケーションの処理遅延のボトルネックになっているか突き止めることができます
  - トレースを構成する最小単位を`Span`と言います
    - 1つのトレースは複数のSpanで構成されています

#### 処理の流れ
「ユーザーが購入ボタンを押すと、まずトレース全体を表す親Spanが生成されます。  その中で認証・在庫確認・決済といった各処理が子Spanとして記録されていきます。 在庫確認の中でDBアクセスが発生すれば、それは孫Spanとしてぶら下がる形になります。 このように、1つのリクエストが通過した処理の流れが、親子関係のツリーとして可視化されるのがトレースの特徴です。

  ```mermaid
  flowchart TB
    subgraph Parent[親Span]
        A[購入リクエスト]
    end
    subgraph Child[子Span]
        B[認証処理]
        C[在庫確認]
        D[決済処理]
    end
    subgraph Grandchild[孫Span]
        E[DBクエリ]
    end
    A --> B
    A --> C
    A --> D
    C --> E
  ```

### メトリクスとは？
システムの状態やパフォーマンスを「数値」で集計したものです。

従来のインフラ監視でもお馴染みのCPU使用率やメモリ使用量、リクエスト数などを時系列で記録し、システム全体の傾向や健全性を把握します。

#### OTelで扱うメトリクスの種類
| 種類 | 説明 | 例 |
|------|------|-----|
| **Counter** | 増加のみする累積値 | リクエスト数、エラー数 |
| **Gauge** | 上下する瞬間値 | CPU使用率、メモリ使用量 |
| **Histogram** | 値の分布 | レイテンシ（p50, p95, p99） |

#### トレースとの使い分け
| 観点 | トレース | メトリクス |
|------|---------|-----------|
| 粒度 | 個々のリクエスト | 集計値（合計・平均） |
| 用途 | 原因調査・ボトルネック特定 | 傾向把握・アラート |
| 問い | 「なぜ遅い？」 | 「今、異常か？」 |

### 収集したテレメトリデータの流れ

#### アプリケーション側（API / SDK）
- `API`: 「何を計測するか」を定義するインターフェース
- `SDK`: 「どう処理・送信するか」を実装するライブラリ
- `Exporter`: Collectorへデータを送信（OTLP形式）

#### Collector側
- `Collector`: 受信→加工→送信を行う中継役
- `Receiver`: データの入り口（OTLP、Prometheusスクレイピングなど）
- `Processor`: バッチ処理、フィルタリング、属性の加工
- `Exporter`: バックエンドへ送信（Jaeger、Prometheus、Datadogなど）

この構成によりアプリケーションはCollectorの宛先だけ知っていれば良く、バックエンドの変更や認証情報の管理はCollector側で一元管理できます。

```mermaid
flowchart TB
    subgraph App[アプリケーション]
        A1[API: 計測] --> A2[SDK: バッチ処理・装飾] --> A3[Exporter: OTLP送信]
    end

    subgraph Collector[OpenTelemetry Collector]
        C1["Receiver<br>(OTLP受信)"] --> C2["Processor<br>(加工)"] --> C3["Exporter<br>(送信)"]
    end

    subgraph Backend[バックエンド]
        B1[Prometheus]
        B2[Jaeger]
        B3[CloudWatch]
    end

    A3 --> C1
    C3 --> B1
    C3 --> B2
    C3 --> B3
```

## 6. 実装
上記を踏まえて、研修ではEKS上にPodとしてCollectorをサイドカーとしてデプロイし、最終的にはApplication SignalsのAPM上にトレースとメトリクスのデータを可視化しました。
- OpenTelemetry SDK
- AWS Distro for OpenTelemetry Collector

### SDKの実装
- GoのSDKを用いて実装します。Middlewareとして全エンドポイントのトレース、メトリクスを収集します。
- トレース周りはGin用のパッケージがあるのでそちらを利用していて、メトリクスは日滞納のため自分で実装しています。
```go: app/middleware/otel.go
package middleware

import (
	"context"
	"time"
	"errors"

	"github.com/gin-gonic/gin"
	"go.opentelemetry.io/otel"
	"go.opentelemetry.io/otel/attribute"
  // ローカルで検証する際はこれを使用する。
	// stdouttrace "go.opentelemetry.io/otel/exporters/stdout/stdouttrace"
	"go.opentelemetry.io/otel/metric"
	sdkmetric "go.opentelemetry.io/otel/sdk/metric"
	sdktrace "go.opentelemetry.io/otel/sdk/trace"
)

type OtelMetricsMiddleware struct {
	requestCounter  metric.Int64Counter
	requestDuration metric.Float64Histogram
	shutdown        func(context.Context) error
}

func (m *OtelMetricsMiddleware) Shutdown(ctx context.Context) error {
	return m.shutdown(ctx)
}

// Tracer用のセットアップ
func newTracerProvider(exporter sdktrace.SpanExporter) (*sdktrace.TracerProvider, error) {
	return sdktrace.NewTracerProvider(
		sdktrace.WithBatcher(exporter),
	), nil
}

// Meter用のセットアップ
func newMeterProvider(exporter sdkmetric.Exporter) *sdkmetric.MeterProvider {
	return sdkmetric.NewMeterProvider(
		sdkmetric.WithReader(sdkmetric.NewPeriodicReader(exporter, sdkmetric.WithInterval(30*time.Second))),
	)
}

func SetupOTelSDK(ctx context.Context, metricExporter sdkmetric.Exporter, traceExporter sdktrace.SpanExporter) (*OtelMetricsMiddleware, error) {
	var shutdownFuncs []func(context.Context) error

	shutdown := func(ctx context.Context) error {
		var err error
		for _, fn := range shutdownFuncs {
			err = errors.Join(err, fn(ctx))
		}
		shutdownFuncs = nil
		return err
	}

	// トレースの収集
	tracerProvider, err := newTracerProvider(traceExporter)
	if err != nil {
		return nil, err
	}
	shutdownFuncs = append(shutdownFuncs, tracerProvider.Shutdown)
	otel.SetTracerProvider(tracerProvider)

	// メトリクスの収集
	meterProvider := newMeterProvider(metricExporter)
	shutdownFuncs = append(shutdownFuncs, meterProvider.Shutdown)
	otel.SetMeterProvider(meterProvider)

	meter := meterProvider.Meter("go-app")

	requestCounter, err := meter.Int64Counter("http_requests_total",
		metric.WithDescription("Total number of HTTP requests"),
	)
	if err != nil {
		return nil, err
	}
	requestDuration, err := meter.Float64Histogram(
		"http_request_duration_seconds",
		metric.WithDescription("HTTP request duration in seconds"),
	)
	if err != nil {
		return nil, err
	}

	return &OtelMetricsMiddleware{
		requestCounter:  requestCounter,
		requestDuration: requestDuration,
		shutdown:        shutdown,
	}, nil
}

func (m *OtelMetricsMiddleware) OtelMetrics() gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Next()

		status := c.Writer.Status()
		attrs := []attribute.KeyValue{
			attribute.String("method", c.Request.Method),
			attribute.String("path", c.FullPath()),
			attribute.Int("status", status),
		}

		m.requestCounter.Add(c.Request.Context(), 1, metric.WithAttributes(attrs...))
	}
}

```
```go:app/main.go
package main

import (
	"context"
	"html/template"
	"log"

  // moduleの設定のため各環境に依存します。
	"go-api/middleware"
	"go-api/routes"
	"go-api/utils"

	"github.com/gin-gonic/gin"
	"go.opentelemetry.io/contrib/instrumentation/github.com/gin-gonic/gin/otelgin"
  // 開発用のエクスポーター
	// "go.opentelemetry.io/otel/exporters/stdout/stdoutmetric" 
	// "go.opentelemetry.io/otel/exporters/stdout/stdouttrace"
	"go.opentelemetry.io/otel/exporters/otlp/otlpmetric/otlpmetricgrpc"
	"go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracegrpc"
)

func main() {
	router := gin.Default()

	ctx := context.Background()
	metricExporter, err := otlpmetricgrpc.New(ctx, otlpmetricgrpc.WithInsecure())

	if err != nil {
		log.Fatalf("failed to initialize metric exporter: %v", err)
		return
	}

	traceExporter, err := otlptracegrpc.New(ctx, otlptracegrpc.WithInsecure())
	if err != nil {
		log.Fatalf("failed to initialize trace exporter: %v", err)
		return
	}

	otelMiddleware, err := middleware.SetupOTelSDK(ctx, metricExporter, traceExporter)
	if err != nil {
		log.Fatalf("failed to initialize OpenTelemetry middleware: %v", err)
		return
	}

	defer func() {
		if err := otelMiddleware.Shutdown(ctx); err != nil {
			log.Fatalf("failed to shutdown OpenTelemetry middleware: %v", err)
			return
		}
	}()

  // トレースはotelginのライブラリに任せている
	router.Use(otelgin.Middleware("go-app"))
  // メトリクスはミドルウェアでじそっそうしている
	router.Use(otelMiddleware.OtelMetrics())

  // 別ファイルでhandlerの処理は記載しているが、今回は省略。
	gin.SetMode(gin.ReleaseMode)
	router.SetFuncMap(template.FuncMap{
		"upper_to": utils.Upper,
	})
	router.Static("/static", "./static")
	router.LoadHTMLFiles(
		"templates/index.html",
	)

  // 別ファイルでhandlerの処理は記載しているが、今回は省略。
	router.GET("/", routes.HelloWorld)
	router.GET("/healthz", routes.HealthCheck)
	router.GET("/metrics", routes.Metrics)

	if err := router.Run(":8080"); err != nil {
		log.Fatal(err)
		return
	}
}
```
